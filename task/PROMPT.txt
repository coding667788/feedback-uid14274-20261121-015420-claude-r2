为合规团队实现离线抽查队列。输入包括待审记录、部门和风险层级、每层抽查数的上下界、互斥样本组、可用审查员及其资格和单周容量。每条记录至多入选一次；入选必须分配给合格且不来自该记录部门的审查员。任何互斥组至多选一条，组允许相互重叠。对每条记录声明优先级，审核不改变原记录。同一选择同时满足部门、风险层级的配额，分别对两个维度的每个标签计数，而不是只校验交叉分组。输入还给出必须覆盖的历史事故 ID 集合，一条记录可关联多个事故，且同一个事故至少由两条分属不同部门的入选记录支撑。
plan 最大化优先级总分，再最小化入选数，最后用按记录 ID 排序的 (记录 ID, 审查员 ID) 列表决胜。若无解，diagnose 使用同一模型在输入的配额和事故要求中找一个最小基数矛盾集，按约束 ID 列表决胜；资格、容量和互斥保持硬性。给出整个矛盾集无解及逐个去掉一条后的可行见证。支持 28 条记录、10 名审查员及 16 个可诊断约束，说明上界与缓存使用，不得把可行的近似解报成最优。测试覆盖重叠互斥组、单维分别可满足却无法同时满足、只有某个可调度指派才能达成最高分、事故共同部门不能算独立，以及两个最小矛盾集决胜。

使用 Windows 原生 Python 3.12、标准库和 CPU，从空仓库实现，所有夹具用本地虚构数据。命令格式为 python -m solution <命令> CASE.json，涉及持久状态的命令带 --db DB.sqlite。标准输出为 UTF-8 JSON，同一逻辑输入产生同一结果；结构错误给出可定位的错误码及字段位置。交付可直接运行的样例、README（含完整输入输出定义与复现命令）和可用 python -m unittest discover -s tests -v 执行的断言测试。
